# СВЕТ / 03

Демонстрационный сайт вымышленной московской фотостудии для портфолио веб-разработчика. Реальные услуги не оказываются.

## Статус: код MVP, требуется настройка Supabase

Реализованы адаптивная главная, каталог `/halls` и страницы `/halls/daylight`, `/halls/blank`, `/halls/form`. Залы используют единые типизированные данные, переиспользуемые карточки и шаблон страницы. Есть галереи авторских SVG-заглушек, характеристики, оборудование, условия аренды и другие залы. Неизвестный зал возвращает 404. Метаданные заданы для каталога и каждого зала.

Реализованы интерфейс бронирования, серверные операции Supabase и защищённая админка. Для сохранения заявок требуется настроить реальный проект Supabase и применить миграцию — см. раздел MVP ниже.

## Локальный запуск

Node.js 24 LTS и npm 11. Версии зависимостей зафиксированы в package-lock.json.

```sh
npm ci
npm run dev
```

Откройте http://localhost:3000. Для этапов 1–2 переменные окружения не нужны, список описан в `.env.example`. `.env.local` и секреты исключены из Git.

```sh
npm run lint
npm run typecheck
npm run build
npm start
```

`typecheck` можно запускать отдельно; первая сборка Next.js генерирует собственные типы маршрутов. `npm start` запускает результат production-сборки.

## Структура

- `src/app` — App Router, главная, метаданные и глобальные стили/токены Tailwind CSS 4.
- `src/components` — общие шапка и футер.
- `src/data/rooms.ts` — единый тип `Hall`, данные залов, галереи и тарифы.
- `src/components/hall-card.tsx`, `hall-page.tsx` — общие карточка и шаблон зала.
- `src/app/halls` — каталог, статически генерируемые страницы залов и общий layout.
- `public/placeholders` — оригинальные SVG-заглушки; источники в `SOURCES.md`.

Страницы и общий шаблон залов — серверные компоненты. Только мобильная навигация использует небольшой клиентский компонент: он закрывает нативный `details` после выбора ссылки. Шрифты Onest Variable и IBM Plex Mono хранятся локально через Fontsource; запросы к Google Fonts не нужны.

Дизайн: фон #F6F7F4, текст #1B1D1B, акцент #284B42, максимальная ширина 1360 px. Основная композиция укладывается в 12/8/4-колоночную модульную сетку: половины, трети и четверти, на мобильном — последовательный поток. Отступы 48 px на desktop и 20 px на mobile; промежуточный размер — 32 px.

## MVP: бронирование и администратор

Ветка `feat/booking-mvp` добавляет календарь даты, расписание по часам, выбор интервала, предварительную стоимость, обзор тестовой заявки и результат сохранения с номером и статусом pending. Реальные имя, телефон и комментарии не принимаются. Supabase пока не настроен в облачной среде: без конфигурации интерфейс показывает недоступность расписания и не имитирует сохранение.

### Supabase

1. Создайте проект Supabase. В SQL Editor выполните `supabase/migrations/202610290001_booking.sql` один раз (либо используйте `supabase db push` после подключения CLI к проекту).
2. Создайте пользователя администратора в Auth → Users. Отключите публичную регистрацию, если она не нужна. Не размещайте пароль в коде.
3. Назначьте права через SQL Editor: `insert into public.admins(user_id) values ('UUID_ПОЛЬЗОВАТЕЛЯ');`. Только пользователь из этой таблицы получает доступ к заявкам.
4. Скопируйте `.env.example` в `.env.local`. Заполните URL проекта и publishable key. Service role key приложению не нужен и не должен попадать в браузер. Пароли вводите только в защищённых настройках/локальном окружении.
5. Перезапустите Next.js. Проверьте создание заявки, занятость расписания, вход `/admin/login`, подтверждение и отклонение.

`halls` хранит серверные тарифы. Статические описания в `src/data/rooms.ts` служат для отображения; при изменении тарифов обновляйте оба источника. База проверяет и вычисляет стоимость независимо от браузера. Интервалы хранятся как timestamptz и отображаются по Europe/Moscow. GiST exclusion constraint защищает от пересечений pending/confirmed, включая конкурентные запросы; соседние интервалы разрешены. Отклонение допускается только из pending; обработанную заявку нельзя повторно переводить в другой статус.

Публичные RPC раскрывают только занятые интервалы и создают фиксированного «Тестового гостя». RLS запрещает чтение заявок посетителям, а изменять статусы и очищать заявки можно только через RPC с проверкой администратора. Атомарная общая квота — 20 тестовых заявок в час и 100 за 24 часа, включая прямые RPC-запросы; максимум даты — 180 дней вперёд. Это ограниченный демонстрационный сервис: общая квота может исчерпаться для всех посетителей. Непрерывная доступность под злоумышленной нагрузкой не гарантируется.

### Проверки

- `npm test` — модульные проверки правил времени и пересечений.
- `npm run lint`, `npm run typecheck`, `npm run build`.
- `npm run test:integration` — **только отдельный тестовый Supabase-проект** с применённой миграцией и переменными `TEST_ADMIN_EMAIL`, `TEST_ADMIN_PASSWORD`. Тест удаляет все заявки в начале и в конце, проверяет конкурентные INSERT, цену 4400 ₽ за DAYLIGHT/2 ч, RLS, статусы, соседние интервалы и освобождение после отказа. Не запускайте на проекте с нужными вам заявками. Без доступа к Supabase этот тест не считается пройденным.

Для сброса через UI войдите в `/admin`, введите DELETE в секции сброса и нажмите удаление. Квоты сбросом заявок не обнуляются. Админка показывает последние 100 заявок с фильтром; полная CRM и автоматическое истечение pending не предусмотрены.

### Vercel

Импортируйте репозиторий, выберите ветку MVP и стандартный пресет Next.js. В Environment Variables задайте Supabase URL, publishable key и `NEXT_PUBLIC_SITE_URL` (полный канонический HTTPS URL без завершающего слеша). Для preview используйте отдельный тестовый проект Supabase. Примените миграцию до проверки preview. Для Supabase Auth укажите разрешённые адреса проекта в настройках Auth. Административные страницы имеют noindex; robots запрещает `/admin` и `/api`. Sitemap формируется только при заданном SITE_URL, чтобы не публиковать выдуманный домен.

Публикация production требует разрешения владельца. В текущей среде нет подключённых Supabase/Vercel, поэтому реальное сохранение, авторизация и конкурентные операции на удалённой базе требуют отдельной проверки после настройки.
